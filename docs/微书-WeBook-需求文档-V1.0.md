## 0. 一句话定位

> **让子女用 5 分钟，把"怎么开空调"变成一张看得懂、能打印、会说话的大图说明书。**

微书不试图教会老人用电子产品，它把"会的人脑子里的经验"搬到纸上和屏幕上。

---

## 1. 我们到底在解决什么问题

老人面对电子产品时，障碍其实是四件事，而且它们会互相放大：

| 障碍 | 具体表现 | 微书怎么破 |
|---|---|---|
| **步骤多** | 做到第 3 步忘了第 4 步，或者顺序颠倒 | 一屏一步，物理翻页，做完一步再走下一步 |
| **按钮抽象** | 不知道"那个放大镜图标"到底在哪 | **在实拍照片上画红圈、画箭头**（核心手段） |
| **字体小** | 老花眼、白内障，屏幕字看不清 | 字号可调到极大，配色可切成高对比 |
| **无人可问** | 子女不在身边，做错一次就怀疑设备坏了，产生焦虑 | 纸质版贴墙上 + 手机里点一下就朗读 |

**第四点是最容易被忽略、但最重要的一点**：老人真正需要的不是"会操作"，而是"出问题时不慌"。说明书长期贴在设备旁边，本身就是一种安全感。

---

## 2. 名词定义（后面所有描述都用这几个词）

- **说明书（Guide）**：一份完整教程，例如《和孙子视频通话》《空调制冷怎么开》
- **步骤（Step）**：说明书里的一页卡片 = 1 张照片 + 1 句文字 + 手绘标注
- **创作模式**：教导者（子女/志愿者）使用，可以增删改
- **阅读模式**：受教者（老人）使用，只读，改不动
- **标注**：在照片上手绘的红圈、箭头、序号

## 3. 已确认的产品决策

| # | 决策项 | 结论 | 为什么 |
|---|---|---|---|
| D1 | 目标平台 | **仅 Android** | iOS 需要 Mac + 688 元/年开发者账号，且装到老人手机上极其麻烦 |
| D2 | App 形态 | **一个 App，两种模式** | 教导者做完即可直接给老人看，无需装两个包 |
| D3 | V1 功能范围 | 步骤卡片编辑 + **步骤随时可改** + 手绘标注 + 大字号高对比 + **人声录音** + 朗读 + 导出 PDF/长图 | 控制在 6 项内，确保第一版能真正拿到手上 |
| D4 | 阅读模式翻页 | **大「上一页 / 下一页」按钮** | 老人手指精度低、易手抖，大按钮远比滑动可靠 |
| D5 | 防误改 | **三重保护：长按 3 秒 → 确认弹窗 → 进入后常驻「退出创作模式」按钮** | 老人动作慢，手可能长时间搭在屏幕右上角，单纯"长按 3 秒"会被误触发。所以长按之后必须再点一次确认才算进入，且确认框默认指向"取消"。 |
| D6 | 卡片布局 | **大图在上、大字说明在下，一屏一步** | 图占 60% 高度，字最大最清楚 |
| D7 | 手绘标注 | **要做**（红圈 / 箭头 / 序号） | 对老人理解位置信息，效果远超纯文字 |
| D8 | 构建方式 | **本机全程构建** | 我来操作，你最后拿到 APK |
| D9 | 数据存储 | **纯本地，不联网，不登录** | 老人隐私零风险，断网也能用 |
| D10 | 朗读引擎 | **调用手机系统自带语音引擎** | 不联网、不额外下载，国产手机基本自带中文语音 |
| D11 | 按钮规范 | **重要按钮一律「图标 + 文字」，禁止只有图标** | 老人认字多于认图标，光一个喇叭图标他们不敢按。文字必须写在按钮上，图标只作辅助。 |
| D12 | 步骤修改 | **任何一步都能改，文字 / 照片 / 标注 / 录音四项全部可改** | 说明书是要反复打磨的：拍糊了要换、字写错了要改、录音不满意要重录。步骤列表里每张卡片都带一个显眼的「修改这一步」按钮。 |
| D13 | 人声旁白 | **每步可选录一段创作者本人的声音**，阅读模式里「听家里人说的」优先于「机器朗读」 | 很多老人只听懂方言、或听不惯机器腔。熟悉的儿女声音本身就是安抚，比任何合成语音都有用。没有录音时，机器朗读兜底。 |
| D14 | 保存机制 | **显式保存：进说明书先改草稿，点「保存」才落盘** | 改坏了能整体撤回；误触改乱了不会污染老人看到的内容。未保存就退出时弹窗问一次，三种选择：保存 / 不保存 / 继续改。 |
| D15 | 照片裁切策略 | **默认铺满（可调），另给「完整显示整张照片」一键不裁切** | 铺满能让图占满卡片、字最大；但有些图（长截图、竖拍文档）裁掉就看不全。所以两个都给，由教导者当场看着白框决定。 |

## 4. 功能需求

### 4.1 首页 · 说明书管理

| 编号 | 功能 | 说明 |
|---|---|---|
| F1-1 | 说明书列表 | 卡片式展示：**封面直接用第一步的照片**（老人认图比认字快，一眼看出这份教什么）+ 右下角「N 步」角标 + 名称 + 更新时间。还没有步骤时才退回用封面色块加名字首字 |
| F1-2 | 新建说明书 | 输入名称 + 选择封面颜色（6 色预设，方便老人区分不同设备的说明书） |
| F1-3 | 卡片内直接操作 | 创作模式下，每张卡片直接显示「编辑步骤 / 复制一份 / 删除」三个按钮，不用长按找菜单——教导者是年轻人，直接看到比藏起来更好 |
| F1-4 | 空状态 | 首次打开显示图文引导："拍下第一步的照片吧" |

### 4.2 创作模式（教导者）

进入方式：桌面/首页右上角 **长按 3 秒**（带一个逐渐填充的圆环动画，让人知道要按多久）

| 编号 | 功能 | 说明 |
|---|---|---|
| F2-1 | 步骤列表 | 缩略图列表，可拖动排序、长按删除 |
| F2-2 | 添加步骤（拍照） | 直接调用相机拍照 |
| F2-3 | 添加步骤（选图） | 从手机相册选图 |
| F2-4 | **手绘标注** | 手指在照片上画：红圈、箭头、序号①②③。可撤销、可清空。颜色默认红色，可选黄/黑 |
| F2-5 | 步骤文字 | 每步一句话，**建议 ≤ 30 字**，超出时给出温和提示（不强制） |
| F2-6 | 排版设置 | 字号 5 档（20 / 28 / 36 / 48 / 64）+ 3 套配色预设。**每份说明书独立记忆** |
| F2-7 | 预览 | 一键切到阅读模式自检效果 |
| F2-8 | **保存按钮** | 步骤列表最上方（第一步之前）常驻一条保存条。无改动时显示「保存」；一旦动过任何内容，按钮变为深绿高亮的「保存修改」并呼吸闪动，下面提示"有改动还没保存"。**没点保存就退出，本次改动全部不算** |
| F2-8b | 退出拦截 | 有未保存改动时点「返回」，弹出「这份说明书改过了，要保存吗？」，三个按钮：保存 / 不保存，直接退出 / 取消，我还要继续改。选取消留在原页继续编辑 |
| F2-9 | **修改已有步骤** | 步骤列表每张卡片有一个醒目的「修改」按钮（点卡片任意位置也行）。进去后照片、标注、文字、录音**四项全部可改**；也能在编辑页里直接「删掉这一步」 |
| F2-10 | **录人声（方言旁白）** | 每步可录 ≤120 秒的一段话。录完可**试听 / 重录 / 删除**。录音只存手机本地，不联网、不上传 |
| F2-11 | 录音状态可见 | 步骤列表上带「已录了语音」小标记，一眼看出哪几步有声音 |
| F2-12 | **调整照片（裁切）** | 选图/拍照后先进「调整照片」界面：白框标出老人实际看到的范围，可用手指拖动、两指缩放、也可用「放大 / 缩小」按钮。另有「完整显示整张照片」一键不裁切（两边留底色）。可随时从编辑页再进来调 |
| F2-13 | 标注：序号 | 选「序号」工具后**点一下照片就落一个带圈数字**，序号自动递增；按住可拖动位置。撤销可回退 |

**排版预设（3 套）**

| 预设 | 场景 |
|---|---|
| 白底黑字 | 默认，通用 |
| 黑底黄字 | 强光下或白内障，对比度最高 |
| 米黄底深棕字 | 长时间阅读不刺眼，适合纸质打印预览 |

### 4.3 阅读模式（受教者）

进入方式：默认打开就是阅读模式；创作模式点「退出创作」也回到这里

| 编号 | 功能 | 说明 |
|---|---|---|
| F3-1 | 全屏大卡片 | 图占上方 60%，文字在下方，一屏只显示一步 |
| F3-2 | 翻页 | 底部两个巨大按钮：**◀ 上一步 / 下一步 ▶** |
| F3-3 | **两种听法** | 这一步有录音时，最上面是绿色大按钮「🎤 听家里人说的」；下面才是「🔊 机器朗读」。没录音就只显示机器朗读一个按钮。播放中按钮变绿并显示"正在播放…再点一下就停" |
| F3-4 | 进度提示 | 顶部显示「第 3 步 / 共 6 步」大圆点 |
| F3-5 | 防误改 | 阅读模式下**没有任何编辑入口**，长按无效 |
| F3-6 | 记住位置 | 退出后自动回到上次看到的那一页 |
| F3-7 | **点图片放大** | 点卡片上的照片 → 全屏放大看（和微信点开图片一样）。大字按钮「缩小 / 放大 / 回到原样 / 关闭放大」，也支持拖动和两指缩放。卡片下方常驻一行提示「看不清？点一下上面的照片，能放大了看」 |

### 4.4 导出与打印

| 编号 | 功能 | 说明 |
|---|---|---|
| F4-1 | 导出长图 | 全部步骤竖排拼成一张长图，存到手机相册，可直接微信发 |
| F4-2 | 导出 PDF | A4 纵向排版，**默认每页 1 步**（字最大），可切换每页 2 步省纸 |
| F4-3 | 导出进度可见 | 弹窗不关，实时显示「正在生成 PDF：第 3 / 8 页」，不再干等一个转不动的界面 |
| F4-4 | **文件存两处** | 先落到 App 自己的目录（分享一定可用），再复制一份到公共「下载 → 微书」，**文件管理 App 里能直接翻到** |
| F4-5 | **已导出文件列表** | 导出弹窗最底部列出已经导出的文件：类型图标、文件名（长了自动换行，最多两行）、大小、时间 |
| F4-6 | **分享按钮** | 每个文件右侧「分享」→ 直接调起手机系统的分享面板，可发微信、QQ、蓝牙、打印服务、附近打印店 |
| F4-7 | 删除按钮 | 每个文件右侧「删除」，二次确认后连「下载」里的那份一起删掉 |
| F4-8 | 打印友好 | 白底、留边距、不裁切图片，A4 纸直接打出来就能贴墙 |

> **两个曾经真翻车的坑（已修，别再踩）**：
> 1. 不能用 jsPDF 的 `pdf.save()`——那是"网页里造个下载链接再点一下"，**在 App 的 WebView 里等于什么都没发生**，所以会出现"点了导出、转半天、什么也没有"。必须 `pdf.output('datauristring')` 取出数据交给原生去写。
> 2. 几 MB 的 base64 **不能一整串穿过桥**，会被截断。切成 64KB 一段送过去（`saveBegin / saveChunk / saveEnd`）。

> **技术上的关键保证**：导出时我们不是"截屏"，而是用代码把每张卡片（图片+标注+文字）在画布上重新绘制一遍再输出。**这样中文绝对不会乱码或变方块**，这是很多同类 App 翻车的地方。

### 4.5 人声录音的几条死规则

| 编号 | 规则 | 为什么 |
|---|---|---|
| F5-1 | 录音是**每步可选**，不强制 | 有的步骤（"按一下红色按钮"）一句话就够，录了反而累 |
| F5-2 | 录音**只存在本机**，不联网、不上传、不进 PDF | 家里人的声音属于隐私；纸上也放不出声 |
| F5-3 | 打印出来的纸上**没有声音**，这一点在导出时明确告诉教导者 | 避免"我录了音，贴墙上老人就能听"的误解 |
| F5-4 | 删步骤 / 删录音时，音频文件一并删除，不留垃圾 | 老人手机存储小 |
| F5-5 | 阅读模式**默认引导听录音**（绿色、在最上面），机器朗读降为备选 | 自家人声音的安抚作用不可替代 |

## 5. 关键流程

### 5.1 教导者做一份说明书（目标 ≤ 5 分钟）

```
打开微书 → 长按右上角 3 秒进入创作
  → 新建说明书《和孙子视频通话》
  → 点「+」→ 拍第一步照片（微信图标页）
  → 手指画红圈圈住"微信"图标
  → 打字/说话："第一步，点这个绿色的微信"
  → 想用方言讲？点「录一句家乡话」，说完点停
  → 重复 N 次，直到步骤齐全
  → 哪一步不满意，回列表点「修改这一步」补拍/改字/重录
  → 拖到合适顺序 → 点「排版」调字号和配色
  → 点「预览」自己走一遍
  → 点「导出 PDF」→ 微信发给爸妈 / 直接打印
```

### 5.2 老人用说明书

```
打开微书（就是阅读模式）
  → 看到《和孙子视频通话》大卡片
  → 点进去，第 1 步
  → 看不清？点绿色的「听家里人说的」听一遍（这一步没录音就点「机器朗读」）
  → 照着做 → 点「下一步 ▶」
  → 做到最后 → 完成
```

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 系统版本 | Android 8.0 及以上（覆盖绝大多数老人机） |
| 离线可用 | **全部功能离线可用**，不联网、不上传、无广告、无埋点 |
| 隐私 | 数据仅存本机 App 私有目录，其他 App 读不到；删除 App 数据随之清除 |
| 性能 | 单份说明书支持到 30 步；导出 30 步 PDF 应在 10 秒内完成 |
| **权限时机（D16）** | **打开 App 时一个权限都不问。**老人只读书，不该被弹窗拦。权限只在教导者用到那个功能的那一刻才问一次，系统答应过就记住，之后不再问 |
| 拍照 | **完全不问。**调用手机自带的相机 App 完成拍照，它自己有权限，我们连 CAMERA 权限都不声明 |
| 从相册选图 | 仅 Android 12 及以下的老手机，在第一次点「从相册选图」时问一次「访问照片」；Android 13 起系统直接给临时读取权，不问 |
| 从相册选图（被拒） | 照常打开相册，多数情况仍可选；万一选不了，弹一句"去设置里把照片权限打开"再试 |
| 麦克风权限 | 仅在第一次点「开始录音」时申请；拒绝也不影响其它功能，**机器朗读照常**。录音仅本机使用，**不联网** |
| 导出权限 | 仅 Android 9 及以下的老手机，在第一次导出时问一次「写入存储」；Android 10 起写「下载」目录不需要权限 |
| 录音体积 | 单段 ≤ 120 秒，24kbps 单声道，约 40KB/10 秒；30 步全录约 1.2MB |
| 稳定性 | 老人误触、连点、快速翻页不得崩溃 |
| 无障碍 | 最小可点击区域 ≥ 72×72dp（约为常规的 1.5 倍） |
| **屏幕适配（D17）** | **尺寸一律按比例算，不写死位置。**卡片按「屏宽」和「屏高 × 55%」两者取小；所有文字块最多两行并自动换行，长名字不会一刀切掉 |
| **留白比例（D18）** | 引入比例单位 **`--sp` = 屏幕宽度的 1%**（JS 按容器实际宽度写入，转屏/改窗口自动重算）。卡片内边距、卡片间距、图标与标题的间隙、按钮与按钮的间隙、列表边距、阅读页各块间距，全部写成 `calc(var(--sp) * N)`。大屏自然宽松、小屏自然收紧，不用为每种机型单独写媒体查询 |
| 横向不溢出 | 320dp 窄屏上页面不得出现横向滚动条；按钮里的文字不得被裁掉 |

### 6.1 已知技术风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 部分手机缺中文语音引擎 | 朗读变成英文念中文，或无声 | 首次朗读时自动检测，缺失则**弹窗引导去"设置→语言和输入→文字转语音"安装**，并给出图文说明 |
| 导出 PDF 中文乱码 | 说明书全是方块，直接废掉 | 已采用画布重绘+图片入 PDF 方案，从根上规避 |
| 老人手机存储小 | 照片存不下 | 拍照后自动压缩到长边 1600px，单张约 200KB；录音单段 ≤ 40KB/10 秒 |
| 老人的手机没有麦克风权限 | 录不了音 | 首次录音时申请；被拒后给出"去设置里打开"的说明。**不录音也能正常用**，机器朗读兜底 |
| 录了音但老人不知道能听 | 白录 | 步骤卡片上直接画一个「可以听录音」的牌子；阅读页绿色按钮排在最上面 |

## 7. 技术选型（你只需要知道结论）

| 层次 | 选择 | 一句话理由 |
|---|---|---|
| 开发框架 | **原生 HTML / CSS / JS + Capacitor 6**（不用 Vue/React） | 原型就是产品真身，不做第二次重写；包体小、启动快、离线可靠 |
| 拍照/选图 | Capacitor Camera 插件 | 官方稳定 |
| 语音朗读 | 系统 TTS | 离线、免费、不联网 |
| 人声录音 | MediaRecorder（网页层）→ 打包后走 Capacitor 原生录音插件 | 网页层先跑通，进 APK 后换成原生录音，音质更好、后台不中断 |
| 手绘标注 | 自研 Canvas 画笔 | 掌控力强，随手画的圈能原样导出到 PDF |
| 导出 | Canvas 重绘 → jsPDF（本地打包，非 CDN） | 中文零乱码，且完全离线 |
| 存储 | 本地文件系统 + JSON | 简单可靠，方便以后做备份导出 |

**为什么不选更"高端"的方案**：你的目标是让老人用上，不是技术炫技。这套方案构建快、体积小、中文处理好、以后要加 iOS 也能平滑迁移。

**为什么不引框架**：Vue/React 带来的复杂度（构建工具、依赖管理、版本冲突）对一个 5 个页面的 App 是净负担。原生 JS 写出来的这个原型，打包进 Capacitor 就是最终产品，中间不产生"原型丢一边、正式版重写一遍"的浪费。

## 13. APK 交付说明（M3）

### 13.1 产物

| 项目 | 值 |
|---|---|
| 文件 | `微书-v1.0.apk`（1.7 MB） |
| 包名 | `cn.webook.app` |

| 系统要求 | **Android 8.0（API 26）及以上** |
| 目标 SDK | Android 14（API 34） |
| 联网 | **完全不需要**，安装即用 |

### 13.2 原生壳做了什么

网页本体（`assets/index.html`）就是那份原型，一个字没重写。原生只补了网页做不到的事：

| 能力 | 做法 |
|---|---|
| 把网页挂到 `https://webook.local` 虚拟域 | 用 `WebViewAssetLoader`。**这一步很关键**：录音必须在安全上下文里才被允许，直接用 `file://` 加载会录不了音 |
| 相机拍照 / 相册选图 | 接管 `<input type=file>`，调起系统相机或相册；拍照走 FileProvider |
| 录音（方言旁白） | 放行 `onPermissionRequest` 的麦克风请求 |
| 朗读 | 调**系统语音引擎**（不是浏览器语音），语速调慢到 0.85 |
| 导出 PDF / 长图 | 网页把文件转成 base64 交给原生，写进手机的「下载 → 微书」目录 |
| 弹窗 | 接管 `alert / confirm / prompt`，否则新建说明书（用了 prompt）会卡死 |

### 13.3 怎么装到手机上

三种方式任选：

1. **USB 连电脑**（最快）：手机开「开发者选项 → USB 调试」，电脑上跑
   `C:\Users\jinglu\AppData\Local\Android\Sdk\platform-tools\adb.exe install 微书-v1.0.apk`
2. **发到手机安装**：用微信/QQ 把 APK 传给自己，手机上点开 → 系统会提示「未知来源」，允许一次即可
3. **拷进手机存储**：USB 传文件到手机，用文件管理器点开安装

**打开不需要任何权限**——老人点开就能读说明书，一个弹窗都不会有。

权限只在教导者真正用到时，手机问一次（答应过就永久记住）：

| 什么时候 | 手机问什么 | 不给会怎样 |
|---|---|---|
| 点「拍一张照片」 | **不问**（调用系统相机 App） | 正常拍照 |
| 点「从相册选图」 | Android 12 及以下才问「访问照片」 | 多数情况仍能选；选不了会给提示 |
| 点「🎤 开始录音」 | 问「使用麦克风」，问之前会先说明一句 | 只是录不了方言旁白，**机器朗读照常可用** |
| 点「导出 PDF / 长图」 | Android 9 及以下才问「写入存储」 | 存不进「下载」，其他功能不受影响 |

### 13.4 这一版的边界（M4 解决）

| 限制 | 说明 |
|---|---|
| 数据存在 App 内部存储 | 已经比网页版稳（卸载 App 才会丢），但照片多了仍受约 5MB 的网页存储上限 |
| 导出只写到「下载 → 微书」 | 还不能一键发微信，M4 加 |
| 没有云同步 | 本来也不打算做；换手机需要靠导出/导入 |

| 限制 | 原因 | 何时解决 |
